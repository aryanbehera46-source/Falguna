# Falguna Bootstrap v0.5 — operational usability

## Frozen acceptance checklist

- One bounded objective enters through the existing mission/control-plane command surface.
- Status presents meaningful milestones without benchmark internals.
- Summary presents requirement coverage, native tests, browser applicability/result, review, changed files, cost, risk, unresolved issues, artifact hashes, audit validity, and merge state.
- Failures map to an actionable category: model, tool, verification, permission, security containment, budget, or human input.
- A `DONE_CANDIDATE` presents Approve Merge, Reject, and Request Changes.
- Decisions record human intent only; protected-main merge remains impossible in this bootstrap.
- One representative end-to-end acceptance ends with approval `PENDING`, no merge, no deployment, and no human candidate-solution coding.

No acceptance gate, isolation boundary, checkpoint, review, audit, evidence, or cost control from v0.4 may be weakened. No broader Company OS function is in scope.
