## 2. Bugs found and fixed this pass

**Bug #1 -- Needs Aryan permanently cluttered with dead items.** Your real production database had 3 Falguna Engineering runs that had already terminally `FAILED` days ago, with no pending merge decision, that would have sat in the Needs Aryan queue forever with nothing anyone could do about them -- exactly the failure mode item 12 asked me to check for. Fixed in `falguna/ttt_hq.py`: a run in a terminal state (`FAILED`/`DONE_CANDIDATE`/`CANCELLED`/`QUARANTINED`) with no pending merge is now excluded from the "pending" list. Nothing was deleted -- I checked directly against your real database and the 3 stale runs are still there with `status=FAILED`, fully intact for audit/history. A resumable `PAUSED` run is deliberately still surfaced (added a regression test to prove the fix doesn't over-filter). Verified against your real production database: 3 stuck items before, 0 after.

**Bug #2 -- Editing an opportunity was completely broken.** `OpportunityStore.update()` existed and worked correctly in Python, but no HTTP route ever called it, and the UI had no Edit button at all. A live `POST /api/rh/opportunities/<id>` returned 404 and a follow-up GET confirmed the field was genuinely unchanged. This directly fails checklist item 1 ("edit it"). Fixed: added the missing `POST /api/rh/opportunities/<id>` route in `falguna/hq_web.py` (matched by exact path-segment count so it can't collide with the existing `/qualify`, `/stage`, `/won`, etc. suffixed routes), and added a real Edit form (title, client, description, budget, skills, deadline, contract type, location, urgency) to the opportunity detail card in the UI. Added 4 unit tests and 1 live-HTTP test.

**Bug #2b -- Active Job payload silently dropped deadline/deliverables/notes.** Checklist item 6 explicitly asks the Active Job to contain "client; opportunity; scope; price; deadline; deliverables; notes." The job payload only ever carried title/requirement/client/price. Fixed in `ActiveJobStore.create_from_won_opportunity()`: `deadline` now comes straight from the opportunity's own field, `deliverables` is the real approved-proposal scope when one exists, and `notes` summarizes the opportunity's urgency/contract-type/location context when present -- and stays honestly `None` rather than inventing anything when the underlying data doesn't exist. Also added these fields to the Active Jobs UI card, which previously showed only the job id and status with none of the underlying data visible at all. Added 2 unit tests + 1 live-HTTP test.

**Bug #3 -- Duplicate Won actions created duplicate Active Jobs.** Checklist item 6 explicitly asks for this to be checked. I confirmed it live: calling "Create Active Job" twice for the same Won opportunity created two independent job rows. Fixed: `create_from_won_opportunity()` is now idempotent -- if an Active Job already exists for that opportunity, it returns the existing one instead of creating a second. Added a regression test.

All four fixes are in the attached patch (`ttt_rh_qa_fixes.patch`), on top of the previously-delivered Revenue Hunter patch. **No features were added beyond these bug fixes** -- everything in the diff is either a fix for a bug found during this QA pass, or the tests proving it.
